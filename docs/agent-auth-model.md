# Agent auth model — Max first, canned status acks, another model only for a capability Claude lacks

Full detail lives here rather than in `agent/CLAUDE.md` (that file is loaded into every agent turn, so it keeps only the compact rules; this file is read on demand). The compact rule in `agent/CLAUDE.md` is authoritative if the two ever disagree; update both together.

## Auth Model — Max first; Claude runs on Max only; another model only for a capability Claude lacks

This is a hard architectural invariant. It is NOT a fallback chain; it is the only permitted behaviour. Strong preference for the Max subscription; a non-Anthropic model is the narrow exception described under "Non-Anthropic models" below. It is not an absolute ban on any other model: Jev runs on its own provider key.

- **Both agents (chat + ops)** run on the **Max subscription**, authenticated via the **login keychain** (`Claude Code-credentials` generic-password item) — **not** `~/.claude/.credentials.json`. The client resolves credentials **keychain-first** (`combine(keychain, plaintext)`), falling back to the plaintext file only when the keychain read returns null, and nothing can invert that order. **Do not create `~/.claude/.credentials.json` on this host, and do not "migrate" the token into it** (`fix-creds.sh`-style copy scripts included): keychain-first means the copy is never read while the keychain is healthy, and it is *not* refreshed on the normal path, so it rots into a superseded refresh token that surfaces as `401 OAuth access token has been revoked` the moment the keychain briefly goes unreadable and the client falls back to it. Two credential stores holding different refresh tokens IS the outage. If a fallback copy is ever wanted, the only safe shape is continuous bidirectional convergence (newer `expiresAt` wins, synced every tick), never a one-shot copy. The supervisors in `agent/supervisor/` MUST spawn `claude -p` with `ANTHROPIC_API_KEY` stripped from the child env (`unsetEnv: ["ANTHROPIC_API_KEY"]` in `claude-session.mjs`). **Ephemeral `claude -p` forks are Max-only by a guard, not just by convention:** `run-ephemeral-opus.sh` and every other runner or trigger with its own `claude -p` line source `agent/scripts/lib/max-auth-guard.sh`, which (1) unsets every `ANTHROPIC_*` / `CLAUDE_CODE_USE_*` variable plus `CLAUDE_CODE_OAUTH_TOKEN` and `AWS_BEARER_TOKEN_BEDROCK` — `ANTHROPIC_BASE_URL` included, because `claude auth status` keeps reporting claude.ai while it redirects every request — and (2) runs `claude auth status --json` (no model call) and refuses to start unless it reads `loggedIn: true`, `authMethod: "claude.ai"`, `apiProvider: "firstParty"`, `subscriptionType: "max"`. A refusal exits 78, logs `REFUSED`, and pages the system channel; it fails closed on unreadable output. Pinned by `tests/max-auth-guard.test.mjs`. If Max is unavailable for any reason — expired login, network partition, quota exhaustion — **Edva is down. Do not route around the failure.** Silent API-key fallback was forbidden because it hides the real problem: when Max is broken, the user must see it and act (re-login, top up, etc.), not watch a degraded proxy keep answering.
- **The phone-channel ack layer** (`agent/phone-channel/index.mjs` — the "On it…" placeholder and its 5-second refresh) is **canned copy only**: `ACK_INITIAL_MESSAGE`, then the `CANNED_REFRESH_MESSAGES` rotation. No model of any kind writes it. A model-written status line once stated a false fact and produced junk lines even behind a sanitizer; a status line must never state a fact, and fixed copy cannot.
- **No component is permitted to make API-key-billed Anthropic calls** — with exactly one exception, the wiki fallback below. `ANTHROPIC_API_KEY` is not read from `.env`, not passed to children, and not used as a fallback anywhere. Adding an `Anthropic` import or `fetch(api.anthropic.com)` outside the agent supervisors and `lib/api-fallback.mjs` violates this rule.
- **No chat→ops rerouting, no alternate-key fallback, no cross-model retry.** Any code that tries to keep Edva "working" when Max is unavailable must be removed on sight. The design intent is: agents up on Max, or agents down; no in-between.

The local LLM helper (`lib/local-llm.mjs`) is intentionally generic — it defaults to `gemma3:1b` but accepts `{model, system, messages, maxTokens, ...}` so other low-stakes, non-agent tasks (quick classifications, one-shot rewrites, offline summarization) can reuse it without reaching for the API key. Anything routed through it must still work when Ollama is unreachable.

## The wiki's API fallback (the one exception)

An automatic switch to the API (Sonnet) when the Max subscription is unavailable, scoped to **the wiki answers only** and capped per month (`WIKI_API_MONTHLY_CAP_USD`, default 25). Everything else above still holds: agents, supervisors and every other job stop when Max is down.

- **What may use it:** the callers in `WIKI_CALLERS` (`lib/api-fallback.mjs`): `wiki-answer` (the wiki site / LAN answer panel, `lib/wiki-serve.js`), `wiki-portal` (home-page topic curation), `wiki-facts` and `wiki-triggers` (the nightly typed-fact and trigger-cue writers). Any other caller is refused before a request is built. The batch bins take the API only with `--api-fallback`, which only the launchd runner `run-wiki-assoc-llm.sh` passes, so a hand run (often over SSH, where the fork always reads as signed out) can never bill. `wiki-embed`'s trigger tier runs from cron and is deliberately not a caller.
- **When:** only when the tool-less `claude -p` fork itself says Max is unavailable: `runToollessDetailed` error kind `not_logged_in` (the CLI's auth banner) or `usage_limit` (the CLI's usage-limit status line; literal prefixes in `USAGE_LIMIT_PREFIXES`, one short line only). A timeout, empty output or non-zero exit is not Max being unavailable and fails the rung as before. After one such answer the rung skips the fork for 5 minutes. When Max returns, the next fork succeeds and the API stops being called.
- **What it calls:** the Sonnet id pinned in `agent/config/models.env`, through the official `@anthropic-ai/sdk`, one user message, no tools, `output_config.effort` as the call site asked, and `fallbacks: "default"` (beta `server-side-fallback-2026-07-01`), so a classifier decline in a category Anthropic reroutes is retried server-side. `stop_reason: "refusal"` is an error, never an answer.
- **The key:** `EDVA_WIKI_API_KEY` in `.env`, canonical copy in the password manager. It is a 30-day key: watch `edva-wiki-api-key-refresh` reminds three days before it expires, and a 401/403 from the API pages the system channel once per day. Not `ANTHROPIC_API_KEY`: that name would make every `claude -p` child bill the API instead of Max, and `max-auth-guard.sh` scrubs every `ANTHROPIC_*` variable. The key goes to the SDK constructor and is never exported to a child. `WIKI_API_FALLBACK=0` turns the whole path off.
- **Budget and breaker:** every call appends a priced row (list price $2/$10 per MTok in/out, every attempt in `usage.iterations`) to `agent/logs/api-fallback/ledger.ndjson`. Before a call, this UTC month's spend plus in-flight reservations plus the call's worst case (prompt estimate and `max_tokens` at full price) must stay under `WIKI_API_MONTHLY_CAP_USD` (default 25), so the cap is never overshot; an unreadable ledger fails closed. Pages (system channel, `--intent wiki-api-fallback`): once per local day the fallback is used, once at 80% of the month, once when the cap stops it.
- **Data:** the same Anthropic model reading the same pages, billed per call under Anthropic's commercial API terms instead of the Max subscription. Health and bank pages the answer panel retrieves for an authorised viewer are included; set `WIKI_API_FALLBACK=0` to keep them on Max only.

Tests: `tests/api-fallback.test.mjs`, `tests/jev-claude-toolless.test.mjs` (usage_limit).

## Non-Anthropic models

The policy: Jev is already in use, and other models may be used when a use case actually needs them. There is a strong preference for the Max subscription; another model is considered if (and only if) it has a capability Claude doesn't have.

The test is capability, not cost: **if Claude can do the job, it runs on Max.** A cheaper, faster or more convenient model is not a reason. Approved and live today: Jev (TypeSafe — calibrated decision probabilities, `docs/jev.md`). Capabilities Claude lacks that a competitor review surfaced as candidates: image/video generation (`agent/capabilities/create-image.mjs` takes an injected provider), real-time speech-to-speech voice, and outbound phone calls to businesses. Each still needs the user's go-ahead for that use case. Non-model data APIs (search, banking, media, meetings, …) are not models and are outside this section.

Each new model ships with:
- its key in `.env`, canonical copy in the password manager;
- a budget check and a breaker that page the system channel once (the `jev-budget-check` pattern);
- an entry under External Dependencies in `system/architecture.md`.

What stays fixed:
- **No non-Anthropic model stands in for Claude.** It may not serve a chat/ops agent turn, act as a fallback when Max is down, or replace the Sonnet/Opus rungs of the model ladder. Max down still means Edva is down.
- **Health and bank rows stay Edva-model-only.** Jev decision calls are the only exception (`agent/CLAUDE.md` § Financial Operations #5).

Changes to this invariant require an explicit change to this rule + `system/architecture.md`. Do not introduce conditional fallbacks in any supervisor, wrapper, or MCP server.
